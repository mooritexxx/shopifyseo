# PostgreSQL cutover and durable runtime

In-repo tools so CoS can **dry-run** a SQLite → Postgres load, apply the load
into a Postgres database, and (after a post-flip sweep) mark the box live on
Postgres.

`scripts/pg_cutover.sh` does **not** flip uvicorn. The live switch is the
marker file written by [`scripts/mark-pg-live.sh`](../scripts/mark-pg-live.sh)
and honored only by [`scripts/start-app.sh`](../scripts/start-app.sh). A stale
`tmp/pg-cutover-*/cutover_mark.json` from a rolled-back `--apply-load` does
**not** count.

Plans 1–7 (portability layer, portable SQL, dual-backend tests) and the
production PG compat layer (`shopifyseo/db/pg_runtime.py`) are already on
`main`. This document is the box runbook.

## What `pg_cutover.sh` does not do

- Does **not** set live `DATABASE_URL` or write it into `start_app.sh` /
  `scripts/dev-restart-local.sh`.
- Does **not** source `pg.env` into the parent shell / uvicorn.
  `scripts/pg_cutover.sh` sources CoS-owned `pg.env` into **its own** process
  only. `scripts/start-app.sh` sources `pg.env` only when the **live mark**
  exists.
- Does **not** delete `cluster_keywords` orphans unless you pass
  `--delete-cluster-orphans`.
- Does **not** `VALIDATE` foreign keys unless you pass `--validate-fks`.
- Does **not** run optional post-cutover type migrations (booleans,
  timestamptz, jsonb, vector indexes). Those stay out of scope.

`start_app.sh` and `scripts/dev-restart-local.sh` are **dev-only**. They do
not honor the live mark. Box restarts go through `scripts/start-app.sh`.

## Required environment

Create a CoS-owned file **outside the repo**, mode `600`:

```bash
mkdir -p /home/box/.config/shopifyseo
cp scripts/pg_cutover/pg_env.example /home/box/.config/shopifyseo/pg.env
chmod 600 /home/box/.config/shopifyseo/pg.env
# edit: PGPASSWORD / CUTOVER_DATABASE_URL / SQLITE_PATH
# After the post-flip sweep: add DATABASE_URL (live app URL), then mark-pg-live.sh
```

Default path: `$HOME/.config/shopifyseo/pg.env` (override with `--env-file` or
`SHOPIFYSEO_PG_ENV`).

| Variable | Purpose |
| --- | --- |
| `CUTOVER_DATABASE_URL` | Postgres URL for dry-run load + Python verifiers. **Prefer this over `DATABASE_URL` during load.** |
| `PGHOST` `PGPORT` `PGUSER` `PGPASSWORD` `PGDATABASE` | libpq / `psql` / pgloader |
| `SQLITE_PATH` | SQLite file to **copy** from (must be a snapshot for `--apply-load`; see below) |
| `CUTOVER_LIVE_DATABASE` | Database name for `--apply-load` (default `shopifyseo`) |
| `PGLOADER` | Optional pgloader binary name |
| `DATABASE_URL` | Live app URL. Required in `pg.env` **after** `mark-pg-live.sh`. `start-app.sh` sources it only when the live mark exists. |

Never commit `pg.env`, passwords, or a real `DATABASE_URL`. The example file
has placeholders only. `.gitignore` lists `pg.env` / `*.pg.env`.

## Box Postgres after a reset

The box is periodically reset. Everything outside `/home/box` is wiped,
including apt packages and `/var/lib/postgresql`. Cluster data must live
under `/home/box`.

```bash
./scripts/ensure-postgres.sh
```

- Installs PostgreSQL 17 binaries if they are missing (apt; adds the PGDG
  repo if `postgresql-17` is not in the current sources). Installs
  `postgresql-17-pgvector` when that package is available.
- Data directory: `/home/box/pgdata/17/main` (override with `PGDATA_DIR` or
  `--pgdata`). Port: `5432` (override with `PGPORT` or `--port`).
- `initdb` **only** when the data dir is missing or empty. A non-empty
  directory is never overwritten or re-initialized.
- Starts the cluster if it is not running; no-op if it is already running.
- Does **not** create or alter roles/passwords, and does **not** create the
  `shopifyseo` database, unless you pass `--bootstrap`. `--bootstrap` creates
  the role and database only when they do not exist; it never changes an
  existing password.
- Safe to run while Postgres is already up. Never prints secrets.

If a Debian cluster config still points at `/var/lib/postgresql/17/main`,
this script leaves it alone. Migrating that data into `/home/box` is a
**manual operator step**: stop that cluster, copy the data directory to
`$PGDATA_DIR`, then start via `ensure-postgres.sh`. Do not delete the old
config until you have confirmed the copy.

`scripts/start-app.sh` runs `ensure-postgres.sh` on every start so a reset
brings the cluster back from `/home/box/pgdata`.

## SQLite snapshot for `--apply-load` (required)

`scripts/pg_cutover.sh` (~line 145) runs `PRAGMA wal_checkpoint(FULL)` on the
`--sqlite` path. That mutates the source file's WAL. **Never** point
`--apply-load` (or `--dry-run` against the live catalog) at the live
`shopify_catalog.sqlite3` while uvicorn is running.

Make a snapshot with the Python `sqlite3` backup API while uvicorn is
**stopped**, then pass that snapshot as `--sqlite`:

```bash
# uvicorn must be stopped first
python3 - <<'PY'
import sqlite3
from pathlib import Path
src = Path("/home/box/workspace/shopifyseo/shopify_catalog.sqlite3")
dst = Path("/home/box/backups/shopify_catalog.snapshot.sqlite3")
dst.parent.mkdir(parents=True, exist_ok=True)
src_conn = sqlite3.connect(src)
dst_conn = sqlite3.connect(dst)
try:
    src_conn.backup(dst_conn)
finally:
    dst_conn.close()
    src_conn.close()
print(dst)
PY

./scripts/pg_cutover.sh --apply-load \
  --env-file /home/box/.config/shopifyseo/pg.env \
  --sqlite /home/box/backups/shopify_catalog.snapshot.sqlite3
```

`--dry-run` has the same `wal_checkpoint` call. Use a snapshot there too if
you care about the live file.

## Dry-run

Needs: `pg.env`, `pgloader`, `psql`, `python3`, `pip install -e '.[postgres]'`.

```bash
./scripts/pg_cutover.sh --dry-run \
  --env-file /home/box/.config/shopifyseo/pg.env \
  --sqlite /path/to/shopify_catalog.snapshot.sqlite3
```

What happens:

1. `PRAGMA wal_checkpoint` + copy the SQLite file into `tmp/pg-cutover-<utc>/`.
   The source file is checkpointed (hence the snapshot rule above).
2. Pre-fix the **copy**: empty strings in numeric columns → NULL/0; text values
   in declared INTEGER epoch columns (including `keyword_metrics.updated_at`)
   → unix seconds.
3. `pgloader` using `shopifyseo.load` (`include drop`, `no foreign keys`).
4. `post_load_fixups.sql` (text-in-int leftovers if pgloader widened a column).
5. Report `cluster_keywords` orphans. **Keep them** unless you passed
   `--delete-cluster-orphans`.
6. `post_load_constraints.sql`: expression indexes + FKs `NOT VALID`.
7. Identity reset (`ensure_identity` / `setval`). Skips `seo_change_events`.
8. `ANALYZE`.
9. `verify_counts.py` then `verify_values.py`.
10. Write `cutover_mark.json` in the work directory (apply-load bookkeeping
    only — **not** the live mark).

`--validate-fks` runs `ALTER TABLE cluster_keywords VALIDATE CONSTRAINT …` and
will fail if orphans remain.

`--skip-pgloader` is for re-running fixups/verify against an already-loaded
database (also what the unit tests exercise).

## Apply load (still not the app switch)

When Salar has approved **loading** Postgres but not yet flipping the app:

```bash
./scripts/pg_cutover.sh --apply-load \
  --env-file /home/box/.config/shopifyseo/pg.env \
  --sqlite /path/to/shopify_catalog.snapshot.sqlite3
```

This rewrites the target database name to `CUTOVER_LIVE_DATABASE`
(default `shopifyseo`) and runs the same pipeline. It still does **not**
export `DATABASE_URL` for uvicorn and does **not** write the live mark.

## Live mark (the app switch)

After `--apply-load` **and** the post-flip sweep passes:

1. Put the live `DATABASE_URL` in `/home/box/.config/shopifyseo/pg.env`
   (mode `600`). Do not commit this file.
2. Write the live mark (host/dbname/user/git SHA — **no password**):

   ```bash
   ./scripts/mark-pg-live.sh --notes "post-flip sweep passed"
   ```

   Default path: `/home/box/.config/shopifyseo/pg_live_cutover.json`
   (override `SHOPIFYSEO_PG_LIVE_MARK`). Refuses if `pg.env` /
   `DATABASE_URL` is missing or Postgres is unreachable.
3. Restart through `scripts/start-app.sh` (do **not** `unset DATABASE_URL`).

`scripts/start-app.sh`:

- Runs `ensure-postgres.sh` first.
- No live mark → start on SQLite with `DATABASE_URL` explicitly unset.
- Live mark present → source `pg.env`. If `DATABASE_URL` is missing/empty or
  Postgres is unreachable, log and exit nonzero. **Never** silently fall
  back to SQLite.
- Starts `.venv/bin/python3 -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000`
  with `.venv/bin` first on `PATH`, logging to
  `/home/box/logs/shopifyseo-uvicorn.log`. Does not start a second instance
  if that port is already serving.
- `--decide-only` / `--dry-run` prints `sqlite`, `postgres`, or `error`
  without starting uvicorn.

## Rollback

```bash
./scripts/mark-pg-live.sh --remove
# or: rm /home/box/.config/shopifyseo/pg_live_cutover.json
./scripts/start-app.sh
```

That returns the next start to SQLite (`DATABASE_URL` unset). To copy
post-cutover PG writes back onto a SQLite **copy** (not the live file):

```bash
PYTHONPATH=. python3 scripts/pg_to_sqlite_delta.py \
  --mark tmp/pg-cutover-<utc>/cutover_mark.json \
  --create-copy-from tmp/pg-cutover-<utc>/catalog.copy.sqlite3 \
  --sqlite-copy /tmp/shopify_catalog.rollback.sqlite3 \
  --postgres-url "$CUTOVER_DATABASE_URL"
```

- Exports rows whose timestamp column is **newer than** `cutover_epoch` /
  `cutover_at` in the mark file.
- Upserts into `--sqlite-copy` only.
- Refuses paths named `shopify_catalog.sqlite3` and
  `$SHOPIFY_CATALOG_DB_PATH` unless you pass `--allow-live` (do not).

Tables without a known timestamp are skipped (full re-copy those by hand if
needed). See `TIMESTAMP_COLUMNS` in `shopifyseo/cutover/catalog.py`.

## Nightly `pg_dump`

`scripts/pg-nightly-backup.sh` runs `pg_dump -Fc` into
`/home/box/backups/pg/` and keeps the newest 7 dumps. It is a no-op (exit 0)
when the live mark is absent. It never prints `DATABASE_URL`.

```bash
./scripts/install-pg-backup-cron.sh
```

The installer is idempotent (no duplicate crontab lines). Cron itself is
wiped on a box reset; `scripts/start-app.sh` calls the installer so the job
is restored after `ensure-postgres` brings the cluster back.

## Orphans and FK validate

SQLite did not always enforce `cluster_keywords.cluster_id → clusters(id)`.
Those rows load under `no foreign keys`. Default policy: **keep orphans**,
add the FK as `NOT VALID`.

```bash
# report only (default)
./scripts/pg_cutover.sh --dry-run …

# delete, then you may validate
./scripts/pg_cutover.sh --dry-run --delete-cluster-orphans --validate-fks --fail-on-orphans
```

## Data fixes (REPORT)

| Issue | Where it is handled |
| --- | --- |
| `keyword_metrics.updated_at` stored as `CURRENT_TIMESTAMP` text in an INTEGER column | `shopifyseo/cutover/sqlite_pre_fix.py` on the copy; `post_load_fixups.sql` if the PG column is still text |
| Same pattern on other epoch INTEGER columns | `INTEGER_EPOCH_COLUMNS` in `catalog.py` |
| Empty string in INTEGER/REAL columns | pre-fix → NULL, or `0` when the column is `NOT NULL` |
| pgloader sequence not at `max(id)+1` | `resync_sequences.py` / `ensure_identity` |
| `seo_change_events.task_id` must not become IDENTITY | skipped |
| SQLite `LIKE` is ASCII case-insensitive; PG `LIKE` is not (873 vs 867 rows for `%a%`) | `LIKE` → `ILIKE` in `shopifyseo/db/compat.py` `_translate_placeholders` (PG path only) |

## CI

`tests/test_pg_cutover_tooling.py` checks cutover script syntax, SQL guards,
pre-fix, verify, orphan default, and delta-to-copy. It does **not** require
pgloader.

`tests/test_pg_durable_runtime.py` checks start-app decision logic (temp dirs
+ env overrides, no real `/home/box` paths), backup retention, cron
installer idempotency, and `ensure-postgres.sh` refusing to init a non-empty
data dir.

`tests/test_pg_runtime_smoke.py` is the production PG smoke (CI
`backend-postgres` extra step with `DATABASE_URL` set).
